## The three notebooks

- **Accurate sum and dot product** (`accurate_sum_dot`) reproduces Section 6
  of Ogita, Rump and Oishi with the PR 6 bindings:
  - Every error is measured against an exact reference. Each product is split
    exactly (Dekker), and `math.fsum` sums the parts.
  - The bounds (5.8) and (5.11) are asserted on all 2200 samples.
  - The exact accumulator's correct rounding is checked in exact rational
    arithmetic, ties to even included.
  - `gen_dot` costs O(n²), 40 ms at n = 2000, so the n = 2000 sweep draws 200
    samples, and the timing chart runs on random vectors. The first version
    took over 300 s.
- **UKF sigma points** (`ukf_cholesky_vs_ldlt`, `ukf_bearing_only`) tests the
  examples' claim that Cholesky's square roots fail on ill-conditioned
  covariances:
  - Both factorizations are backward stable on Hilbert matrices up to cond
    1.7e16. Their residuals stay below u.
  - The one real difference is an indefinite P: Cholesky raises, and LDLᵀ's D
    gives the inertia, when the unpivoted factorization exists.
  - The float32 bearing-only failure comes from the weights at α = 1e-3
    (W₀ ≈ −986894 in float32). Both filters fail at step 3, on the incoming
    covariance. With α = 1 both run, and match float64.
- **Zero copy** checks each rule of a view over NumPy memory, and runs an RK4
  callback and a two-thread frame pipeline through views. The pipeline fails
  within seconds if a worker raises, instead of hanging the docs build.

## Findings

- **H₁₃ is platform-dependent.** The first CI run failed on both macOS jobs.
  H₁₃'s last pivot is rounding noise: −5.8e-17 on Linux x86-64, where
  Cholesky raises, and +2.0e-14 on macOS arm64, where both factorizations
  complete. The notebook had asserted the Linux outcome. It now asserts that
  the pivot is at noise level, that Cholesky raises exactly when it isn't
  positive, and that any residual is below u.
- **The bearing wrap.** The first version re-rounded every bearing when
  wrapping it relative to the central sigma point. That made the float32
  filters complete, which was an artifact. Now only a bearing more than π away
  is moved, and the float32 failure is back.
- **The C++ examples:**
  - `bearing_only_ukf` advances one filter and factors the same P both ways, so
    its two columns can't differ.
  - Its LDLᵀ sigma points still take `sqrt(D(k))`.
  - `ukf_comparison`'s cond(P) never exceeds about 6e3, and its indefinite test
    uses diagonal matrices.
