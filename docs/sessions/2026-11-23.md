## What was asked

- **Why is there a `.cpp` file in `applications/`?** It is
  `ukf_mixed_precision.cpp`, the experiment from #18 (PRs #66, #67). It
  compares Cholesky, LDL^T and Bunch-Kaufman as UKF square roots in six number
  systems. It lives in mtl5-python, not mtl5, because mtl5 stays free of
  dependencies and this repo already fetches Universal. It builds only with
  `MTL5_BUILD_APPLICATIONS=ON`, which defaults to OFF so that `pip install`
  never compiles it. CI builds and runs it in its own `applications` job.
- **What dtypes are supported?** 25 element types, read from
  `type_suffix<T>()` in `python/src/mtl5_types.hpp`. They are now tabulated in
  `CLAUDE.md`.

## Decisions worth keeping

- **`mtl5_types.hpp` is the source of truth for element types, not the
  docs.** The old `CLAUDE.md` claim ("posit16, posit32 registered across NumPy,
  PyTorch, and pandas") was believed and repeated in an answer before the code
  showed it was wrong. Check `type_suffix<T>()` before stating what is bound.
- **The coverage of each entry point is recorded, not just the type list.**
  The sets differ, and the gaps are deliberate:
  - `dtypes()`/`convert()` cover 17 types. The integer types are left out
    because rounding reals into i8 is a quantization scheme, not a cast.
  - The `universal_dtypes` interop covers 13. `fp8` and `cfloat32` are not
    covered, and `fp8e5m2` is refused.
  - pandas registers `posit16` only.
  - PyTorch and JAX get no custom dtypes, only zero-copy for the native types.

## Notes

- The bound `posit16` is `posit<16,2>`. The UKF experiment uses
  `posit<16,1>`, so its results for "posit16" are not for the format Python
  users get.
