## Decisions worth keeping

- **Factors come back as copies, in MTL5's permutation convention.** The
  properties `L`, `U`, `R`, `row_perm`, `col_perm` and `perm` return
  `SparseMatrix_*` and int64 copies, so they outlive a later `refactor()`. The
  convention is `p[new] = old`, giving `A[row_perm][:, col_perm] == L @ U`.
  That is the inverse of SciPy's `perm_r`/`perm_c`, which is why the names
  differ; the SciPy page shows that `argsort` converts one into the other.
- **Exposing the factors exposed a race.** A getter on one thread could read
  a factor while `refactor()` on another rewrote it. Each factor object now
  holds a `std::shared_mutex`: getters, `solve` and `iterative_refine` read
  under a shared lock, and `refactor` writes under an exclusive one, taken
  after the GIL is released. A subprocess test with a barrier reproduces the
  race without the lock.
- **Every docs page is executed, and asserts what its prose says.** The
  Sphinx build runs with `nb_execution_mode="force"` and `-W`, so a fill
  regression or a stale claim fails the docs build. The assertions check
  deterministic quantities only (fill counts, residuals, exponents); timings
  are printed, never asserted, after one wall-clock assert proved flaky.
- **nanobind needs adapting for autodoc.** Sphinx 9 ignored a custom
  documenter, so `docs/conf.py` wraps nanobind functions in the Sphinx process
  instead, moves overload signatures to the end of the docstring, and applies
  NumPy-style section parsing to callables only, because it mangles property
  docstrings that contain colons.
- **Pages deploys only from `main`, and only the latest commit.** The
  workflow skips the deploy if `main` has moved on since the build started,
  so a slow build cannot overwrite a newer site.
- **A local CodeRabbit pass before each push** (`coderabbit review --agent
  --committed --base main`), at the user's request, so that CI and the server
  review run on code that has already been through one round.

## Notes

- `west0479` is vendored in `notebooks/data/` from NIST Matrix Market, with
  its SHA-256 recorded in `notebooks/data/README.md`. Its LU fill under
  `colamd` differs from MATLAB's 5920, because the pivoting differs; the
  notebook says so.
- The SPD page shows that the natural ordering's Cholesky fill of
  `poisson2d` equals the envelope of A exactly. That makes a fill count you can
  check by hand, and the page asserts it.
- Local CodeRabbit passes and server reviews draw on the same allowance of
  about 4–5 reviews per rolling hour. Several local passes in a row left the
  server review rate limited more than once.
- scikit-learn 1.7.0 in the `p311` venv failed a diagonal check; upgrading to
  1.9.1 fixed it.
